# Jospar 2 — результаты проверки

Подготовлен проект из пользовательского ZIP. Исходный архив сохранён отдельно. Основные изменения: спокойный рабочий интерфейс; CSS и JS вынесены из HTML; исправлены мобильная шапка и размеры кнопок; сохраняются черновики; модальные окна блокируют фон; восстановление пароля через Firebase и собственный экран нового пароля; продолжение незавершённого профиля; нет скрытого перехода на демо; история привычек сохраняется; пустые задачи без вымышленных примеров; опросник можно пропустить; три готовых списка вместо восьми; экспорт/импорт; удаление аккаунта; браузерные напоминания при открытом сайте; цели можно связать с проектом; достижения сохраняются после удаления задач.

Сохранение: очередь, видимые ошибки и повтор, резервная локальная копия, контроль конфликтов локальных вкладок и Firestore-транзакций. Сервер: схема данных, единый обработчик ошибок, проверка готовности базы, правильные пути статики, Node 22, lockfile, обновлённый Firebase Admin.

Проверено: пять проверок схемы и HTTP-проверка сервера; браузерные сценарии регистрации, ввода/редактирования/выполнения задач, сохранения после reload, сохранности привычек, связи цели с проектом, экспорта, фокуса диалога и пяти ширин (320/390/768/1024/1440); отдельная проверка экрана смены пароля с имитацией Firebase. npm audit для серверных зависимостей: 0 известных уязвимостей на момент проверки.

Внешняя настройка ещё требуется: Firebase Web config, Authentication Email/Password и Phone, разрешённые домены, Firestore и серверная identity. Реальные письма/SMS, доступ к Firestore и публикация не проверены без пользовательского проекта. Dockerfile подготовлен, контейнер не собирался в этой сессии.

Ограничения: нет фоновой push-доставки при закрытом сайте; нет автоматического слияния конфликтов (нужен экспорт и ручное объединение); локальное демо не является защищённым сервисом аккаунтов; состояние интерфейса всё ещё управляется одним модулем app.js, хотя стили, валидация, сервер и Firebase-адаптер разделены. Дополнительное разбиение интерфейса на компоненты остаётся улучшением архитектуры, а не условием локального запуска. Проверка сброса с имитацией SDK не доказывает доставку реального письма.
