# Подключение jospar-fcaa0 на Spark

Публичная Web-конфигурация и публичный VAPID-ключ уже записаны в `public/config.js`. Это не серверная авторизация и не доказательство, что сервисы Firebase включены. Analytics не подключается. Тариф менять не нужно.

## 1. Включите сервисы в Firebase Console

Откройте https://console.firebase.google.com/project/jospar-fcaa0/overview под аккаунтом владельца.

1. **Authentication → Get started → Sign-in method → Email/Password → Enable.** Для начала используйте почту: реальные SMS не являются бесплатной функцией Spark; доступность/оплата телефонного входа зависят от Firebase. Для учебной проверки телефона настройте тестовые номера в Authentication. Код телефонного входа сохранён, но настоящий SMS на Spark не обещается.
2. **Authentication → Settings → Authorized domains**: добавьте `localhost`, если его нет; проверьте `jospar-fcaa0.web.app` и `jospar-fcaa0.firebaseapp.com`.
3. **Firestore Database → Create database → Production mode.** Выберите постоянный регион базы осознанно: его нельзя просто сменить после создания. Правила будут опубликованы следующим шагом. Не включайте test mode и не открывайте базу всем.
4. **Cloud Messaging**: публичный Web Push VAPID-ключ уже предоставлен и настроен. Должны быть доступны Cloud Messaging API и разрешения на отправку с сервисного аккаунта.
5. Cloud Storage и Cloud Functions для этой версии НЕ нужны: аватарки JPEG 384×384 сохраняются в Firestore, push выполняет отдельный Node.js worker.

## 2. Опубликуйте правила, индексы и HTTPS-сайт

Откройте терминал VS Code именно в папке с `package.json`:

```powershell
npm run setup
npx firebase login
npx firebase use jospar-fcaa0
npx firebase deploy --only firestore:rules,firestore:indexes,hosting --project jospar-fcaa0
```

`firebase login` откроет Google-вход в браузере. Пароли, CLI-токены и приватные ключи никому не отправляйте. На PowerShell при необходимости передайте список как строку: `--only "firestore:rules,firestore:indexes,hosting"`.

Публичный адрес после успешной публикации: **https://jospar-fcaa0.web.app**. Тот же адрес используется в приглашениях. `localhost:8085` другого пользователя — это его компьютер, поэтому для двух разных компьютеров нужен опубликованный адрес.

На этой облачной машине публикация не выполнена: пользовательская Google/Firebase-авторизация не предоставлена. Старые закрытые правила блокируют новую клиентскую интеграцию, пока вы не развернёте новые правила. Индекс collection-group нужен push-worker; после публикации он может строиться несколько минут.

## 3. Проверка регистрации и чата

1. Откройте HTTPS-сайт, создайте аккаунт A, подтвердите почту по письму, вернитесь на сайт и продолжите регистрацию.
2. Во второй отдельной сессии/другом браузере создайте аккаунт B и подтвердите его почту.
3. A → **Команды → Создать команду → Открыть чат → Пригласить**. Укажите email B или оставьте пустым для одноразовой ссылки.
4. Приглашение по email появляется внутри Jospar у аккаунта с этим email. Письмо с приглашением не отправляется: ссылку можно скопировать и переслать самостоятельно. Ссылка одноразовая, действует 7 дней; для email-приглашения требуется именно соответствующий подтверждённый аккаунт.
5. B → **Команды → Принять → Открыть чат**. Сообщения должны появляться у обоих пользователей без перезагрузки.
6. Владелец может удалять участников и передавать права другому участнику. После удаления участника правила запрещают ему читать/писать чат. Для удаления своего аккаунта нужно сначала выйти из команд; владелец сначала передаёт права.
7. **Аватар → Профиль**: фото из галереи, имя, описание; вкладки Аккаунт, Уведомления, Команды. Публичное имя, фото и описание доступны авторизованным пользователям. Личные задачи и email-документ доступны только владельцу.

## 4. Настройте сервер настоящих push-уведомлений

Firestore доставляет сообщения в открытый чат напрямую. Push при закрытой вкладке требует доверенного отправителя; один публичный apiKey/VAPID не может безопасно заменить серверный доступ.

1. Firebase Console → ⚙ → Project settings → **Service accounts → Firebase Admin SDK → Generate new private key**. Если организационная политика запрещает ключи, используйте управляемую серверную identity вместо обхода политики.
2. Сохраните файл **вне проекта**, например `C:/Users/Фархат/.jospar/firebase-admin.json`. **Не присылайте его в чат и не загружайте на GitHub.** Он позволяет серверу обходить клиентские правила и должен быть защищён.
3. Скопируйте `.env.example` в `.env`; замените пути `GOOGLE_APPLICATION_CREDENTIALS` и `FIREBASE_ADMIN_FILE` на свой локальный файл. Значение `JOSPAR_PUSH_WORKER=1` включает отправку. У сервисного аккаунта должны быть права читать Firestore/Auth и отправлять FCM в этом проекте; не назначайте лишние права только ради устранения ошибки.
4. Остановите старый локальный сервер Ctrl+C и запустите:

```powershell
.\start-push.cmd
```

В консоли должны быть сообщения о запуске сайта и **Firebase push worker connected to jospar-fcaa0**. Если второго сообщения нет, доставка push не готова: проверьте вывод об авторизации/индексе.

Для Docker (после настройки `.env`):

```powershell
docker compose -f docker-compose.yml -f docker-compose.push.yml up --build -d
docker compose logs -f
```

5. На устройстве B откройте опубликованный HTTPS-сайт → **Профиль → Уведомления → Включить push**, разрешите уведомления браузеру. В браузере должен зарегистрироваться service worker.
6. Закройте вкладку B, оставив браузер/ОС с разрешённой доставкой. От A отправьте сообщение. B должен получить системное уведомление; нажатие откроет чат команды.

Worker должен продолжать работать. Если выключить компьютер/сервер, чат Firestore останется рабочим, но push-доставка приостановится. Для круглосуточной доставки нужен постоянно работающий сервер. Работа при полностью закрытом браузере, режиме энергосбережения, Focus/DND и на iOS зависит от браузера/ОС; на iOS Web Push обычно требует установленного на главный экран веб-приложения. Это не нативное приложение Telegram.

Worker обрабатывает последние 100 сообщений/приглашений, повторяет временные ошибки и удаляет невалидные токены. Это учебная реализация, не гарантированная доставка всех офлайн-сообщений при долгих простоях. Для больших нагрузок потребуется очередь/outbox и мониторинг. В push не передаётся текст чата, только общее уведомление о сообщении.

## 5. Проверки и границы подтверждения

```powershell
npm test
npm run test:firebase
```

Для Firebase-эмуляторов нужен Java 21+. Тест запускается только с `demo-jospar`, а не с рабочим проектом. `tests/cloud-ui.cjs` проверяет UI двух сессий с явно подменённым SDK и не доказывает безопасность правил или реальную доставку Firebase. Проверка правил отдельно проверяет закрытость личных документов, вход в команду только через приглашение, запрет подделки автора и изоляцию push-токенов.

В текущей облачной среде официальный файл Firestore Emulator блокируется сетевым прокси (storage.googleapis.com, HTTP 403), поэтому тест правил пока не выполнен. Добавление домена сохранено в черновик настроек среды, но требует сохранения/публикации для применения. Сборка и UI-тесты не заменяют проверку правил. Реальные Auth/Firestore/FCM и развёртывание остаются непроверенными до действий владельца проекта.

### Обновление аватарок и просмотра профиля
Фото сначала открывается в локальном редакторе: перетаскивание, масштаб, горизонтальное/вертикальное положение, сброс и отмена. В Firestore записывается только подтверждённый JPEG 384×384 до 120 000 символов. В чате имя открывает публичный профиль без редактирования, аватарка — увеличенное фото. Email и личные планы другого пользователя не запрашиваются. Для этого обновления достаточно публикации Hosting; правила Firestore не изменены.
